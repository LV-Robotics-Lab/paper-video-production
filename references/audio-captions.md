# 声音、剪辑和字幕

## 三份文本分开管理

1. **论文叙述**：事实准确、限定条件完整。
2. **TTS 输入**：按选定声音调整缩写和难读术语的发音。
3. **字幕显示**：标准术语、正确数字与简洁语意单元。

缩写可在朗读文本中展开或写成发音提示，显示文本仍使用论文标准名称。具体发音按作者选择和试听结果记录，不把某个项目的读法变成通用规则。首次合成先试听一小段包含术语的文本，再批量生成；已确认发音不必重复消耗额度。

ElevenLabs、Suno 是可选工具，并非 skill 的硬依赖。沿用用户选定的声音和已有文件；需要账户登录时让用户完成必要的登录步骤，不自行增加订阅或购买。网页操作遵守当前浏览器工具和上传授权规则。

## 语音先决定真实节奏

- 为关键讲解点建立具名 cue（如 `show_inputs`、`compare_result`），由本次音频的词级对齐映射到场景内整数帧。动画引用 cue；改旁白后重新对齐并检查依赖事件，避免在多个场景脚本里逐一调整绝对秒数。音乐卡点不能压缩公式、图表和真实执行的理解时间。
- 按语意段生成，保存原始音频和使用参数。原文件不要覆盖。
- 用词级对齐或 ASR 辅助定位，结合试听选取边界。截取后保留自然呼吸和停顿。
- 词前后约 50–150 ms 的安全余量可以作为检查起点，实际由音素决定；短淡入淡出只去爆音，不能掩盖截断单词。
- 特别试听 “percent” 的词尾，以及前句的尾音是否粘到下一句开头，避免上一句的残留音节粘到下一句。
- 旁白太长时优先删去不必要比较前缀、冗长指标解释，再小幅调速。改音频后重算对齐，不能继续用旧字幕时间。
- 变速保持音高；不得通过加速对比视频制造模型生成速度优势。

## 单行字幕是语意编辑

把一句话拆成可独立跟读的意群，例如：

> The model predicts future observations
>
> from the input sequence and control signals.

两条按声音依次显示，而不是同时放在两行。不要分开 `29.8%`、模型完整名称、数值与单位；尽量不让冠词或介词孤立在一条字幕末尾。若超过宽度，重新分词组及时间，而不是把后半句挤到下一行。

- 1080p 的一个起点是 32–36 px 字号、居中、安全宽度约 1200–1600 px，依据字体和画面密度调整。实测字形宽度比字符数可靠。
- 统计值用 `12.5%`、`0.82`、`2.0×`；自然叙述用 `two inputs`、`three stages`。模型版本号保留原始数字。
- 用户要求用单词表示自然语言计数时，不修改小数、模型版本或实验数据。
- 不强制字幕持续整句话；声音停顿、语意边界和视觉阅读共同决定切换。
- 使用实际渲染字体检查 SRT：

```bash
python scripts/check_captions.py /absolute/path/captions.srt \
  --font /absolute/path/font.ttf --font-size 34 --max-width 1500 \
  --duration 180
```

脚本只读，不自动改写文字或时间。没有字体参数时只能验证结构与时间，不能声称验证了画面宽度；阅读速度提示是人工复核线索。

## 配乐要在旁白下仍能听见

偏好无歌词、低侵入性、缓慢发展且节奏稳定的背景音乐；避免与旁白音色和频段争抢的厚重主旋律。若从参考论文视频借鉴，只分析风格，不假定可以重新使用其音轨。

可用下面的数值作为试听起点，不能当作广播标准或通用正确值：

- 混音成片约 -16 LUFS integrated，true peak 不高于约 -2 dBTP。
- 音乐预处理可从约 -27 LUFS 试起；需结合旁白响度听实际相对音量。
- 温和 sidechain compression 示例：threshold 0.08（线性幅度）、ratio 1.5、attack 100 ms、release 550 ms。
- 开场、间隙、结束适当恢复音乐；淡出尾部覆盖完整谢幕。

测量后再做最终响度处理，避免反复归一化。若说话时完全听不到音乐，先检查 ducking 阈值、比率和音乐基础电平；不要只把整个混音增益提高。分别听耳机和普通扬声器可闻性。记录旁白干声、音乐、混音版本与测量值，以便重排场景时复用。
