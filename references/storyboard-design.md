# 分镜与视觉约束

用于新片、方法段重构或参考风格迁移。短小修改沿用已确认设计，只更新对应镜头；以下字段可放入现有工程，不要求创建一套新文档。

## 从理解目标到可见动作

先确定观众看完应能回答的问题：方法改变了什么、关键机制为什么成立、哪个实验支持结论。按依赖关系安排场景；一场可以含多个镜头，但应有清晰的主要理解目标。

将分镜关联到单一 timeline，避免另一张表独立维护秒数：

| 字段 | 用途 |
| --- | --- |
| scene_id / shot_id | 关联场景代码、音频和验证记录 |
| learning_goal / claim_refs | 观众应理解什么；依据在哪一节、公式、表格或实验 |
| visible_objects / action | 具体可见对象、发生的变化，以及变化所解释的机制 |
| narration_cues | 触发动作的词句或具名事件，不重复手写绝对时间 |
| layout / camera | 主体、标签、字幕区域与取景方式 |
| entry_state / exit_state | 跨镜头保留的对象身份、位置、相机和强调状态 |
| source_assets / render_entry | 实验片段、图层和可重渲染入口 |

例如，讲解“两个观测共享几何信息”：两个带身份标签的观测进入各自分支，在 `shared_geometry` 旁白锚点强调论文规定的交换路径；下一镜继承相同节点位置。若只是机制示意，不能让流动粒子看起来像真实测得的 attention。

公式动画应保存符号身份和变换依据，按论证依赖显露推导；别用平滑变形跳过一个尚未解释的数学步骤。实验镜头则保留原始结果，不为了统一画风把它重画成更成功的执行。

## 把风格写成能检查的约束

选用参考时记录要借鉴的构图、节奏、颜色或运动方式，以及它服务的解释目标。无需把完整风格库加入 skill，也不从风格样片继承故事和素材。

需要探索新风格时，按主题从 [Lemo-Opuscar](https://github.com/lemomo-ai/lemo-opuscar/tree/main/styles) 或 [huashu-art-motion](https://github.com/alchaincyf/huashu-art-motion/tree/main/references) 选少量匹配卡片，读取具体配方后提炼到项目设计说明。方法流程可从 blueprint/信息图语法考察，概念推导可从数学解说/白板语法考察；依据可读性和实际渲染选择，不仅凭风格名字。跨镜头叙事可参考 [PDoomVideo 的分镜](https://github.com/JohnHeibel/PDoomVideo/blob/main/STORYBOARD.md) 如何写清出口状态。用户已有确定风格时直接沿用。

在工程设计说明中明确：

- **语义颜色**：哪个颜色对应输入、方法、baseline、GT；沿用论文已有映射。
- **字体与层级**：实际字体文件、公式排版方式、标题/标签/字幕字号及最小可读尺寸。
- **布局区域**：主体、公式、标签与字幕的边界，注明画布单位；定义世界坐标到屏幕坐标的统一变换。
- **运动语法**：哪些对象固定，哪些移动；高亮顺序、取景目的、入场和退场方式。
- **素材类型**：真实实验、测量图表、机制示意、装饰素材分别如何表现，避免误认。

约束是可调整的设计选择。不要照搬外部 skill 的颜色禁令、单镜字数/秒数上限、运镜数量、运动占比或音效配额。科研公式、坐标轴和完整实验允许较长停留；真实视频、图表和图解可以共存，通过字体、标签、颜色含义和转场保持一致。

## 用实际渲染验证设计

选择最能暴露问题的代表画面：复杂公式、最密集的图、最长标签或关键结果。用最终渲染路径出帧，确认文字、语义颜色和字幕安全区，再制作包含旁白与相邻过渡的短片，核对阅读节奏和对象连续性。

代表帧证明布局，短片检验运动与声音；两者不能互相替代。用户要求看分镜并确认时再等待，否则自行检查后继续完成已授权成片。纯旁白改字不需要重新设计整片。

此方法借鉴 Lemo-Opuscar 的实际风格帧、PDoomVideo 的镜头出口设计、TheoremExplainAgent 的场景学习目标及 huashu-art-motion 的可执行设计约束；具体来源和取舍见 [参考来源](rendering-backends.md#参考来源与采用边界)。
