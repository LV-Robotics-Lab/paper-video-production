# 审片、修复与经验复用

规划、实现和审片是三种工作职责，可由同一 agent 分阶段完成；不要求自动派生多个 agent。成片技术验收仍遵循 [成片与发布](delivery.md)。

## 将问题定位到可修改对象

1. **运行检查**：先处理异常、丢失素材、字体回退和媒体读取失败。记录后端版本与错误位置，查对应版本 API，避免凭猜测反复改写。
2. **画面检查**：检查关键帧与完整受影响短片；从边界框、标签关联、字幕区和遮挡关系发现问题。保存 scene/shot ID、帧或时间区间、对象 ID、画面证据、问题及拟修改项。例如“scene_03 的 145–160 帧，eq_2 标签盖住输出箭头；调整公式区宽度后复查该区间”。
3. **理解检查**：对照分镜的理解目标，检查机制、限定条件和实验依据是否在画面与旁白中一致表达。可用少量预设理解问题诊断遗漏，但自答或 VLM 评分不等于真实观众学习效果。
4. **局部修复**：优先修改出错对象、布局参数或 cue。先处理事实错误、缺失信息、遮挡和截断，再处理装饰。保留已通过的内容；改入口/出口状态时联动相邻转场。
5. **复查闭环**：重渲染相同时间区间，对比修复前后，再播放包含邻接转场的短片。确认没有用缩小到不可读、删除公式或裁掉失败过程来“修好”画面。

画面审查反馈应指出对象和空间位置，必要时关联函数或代码行。可以使用布局网格，但不强制采用 Code2Video 的固定 6×6 分区；截图也不能证明中间帧没有碰撞。VLM 的主观评分是定位线索，科研依据、实际运动和音频须分别检查。

为局部自动修复设置小的尝试预算，例如 3 轮；相同问题连续两轮无改善时改变诊断方式、查文档或简化视觉实现，避免无限调用。到预算仍未解决则保留最佳可审阅版本，报告具体问题，不标记验收通过；其他独立工作继续进行。

## 分开记录各类验证证据

验收记录区分布局、动画播放、语音对齐、听觉审片、媒体解码和来源核对；每项保存所检查的 revision、片段与结论。完整播放到结尾及无解码错误支持播放可用性，抽帧支持对应画面布局，时间线支持 cue 位置；它们互不替代，也不能自动推出全片没有视觉问题或声音自然。

播放器诊断按单次播放记录起止位置、是否结束、错误及可用的丢帧计数。seek 或再次播放后的累计计数应单独记录，避免把一次完整播放的零丢帧结论扩展到所有复查。缺少某种观测能力时，把该项保留为未验证，继续完成其他独立检查。

## 复用已验证经验

开工前优先读取现有工程中的已验证修复记录，按后端版本、对象类型和故障条件挑相关项。无需为了少量案例引入向量数据库。

在项目内保存轻量修复记录，例如 `production-lessons.jsonl`：

```text
id, backend_version, symptom, trigger_conditions,
root_cause, change, evidence_before, evidence_after,
verified_scope, applicability, status
```

- **成功做法**：记录为何有效及适用场景，作为候选方法，避免固化成通用视觉模板。
- **失败教训**：记录故障条件、已验证的原因与有效修复。没有前后证据或同时改动很多因素时，把原因标为待验证，不能把猜测写成硬规则。
- 引用对应 revision 和片段；保留回退点。跨版本经验需要重新验证，不记录密钥、私人反馈原文或大媒体。
- 若用户授权维护跨项目经验库，可把经过复查的条目提升到该库；更新通用 skill 或用户长期记忆需要明确请求。普通视频任务只维护当前项目记录，不自改全局规则。

提升到通用 skill 时，只保留触发条件、可迁移原因、修复方法与验证边界。论文名称、设备、源路径、实际时间戳、帧率、配音选择、前后画面和具体审片记录留在项目工程。不要把一次试片的秒数、字体、配色或场景数量变成默认标准；缺少前后证据的候选改进可记为待验证，不与已验证修复混列。

这是对 ManimAgent 成功经验/失败经验双通道思路的轻量适配，不声称实现或复现其完整系统。它的检索、学习效果及论文指标不自动转化为本 skill 的性能结论。
